# Prototype V2 Progress Tracker

Source of truth for `prototype2/` UI work. Sibling tracker to `progress-prototype.md` (v1). A v2 milestone is `complete` only when the source files compile (`tsc --noEmit`), the dev server boots without errors, the production build succeeds, and the relevant slice of the design system is reviewable in light + dark themes.

Allowed status values: `planned`, `in progress`, `complete`, `blocked`.

## Environment Note

Same host as v1: Fedora Linux (no WSL mount of Windows). `prototype2/` is a browser-only web app — no Tauri, no Rust, no native Windows artifacts. Linux `node`/`npm` is used for install and dev. Lockfile for prototype2 stays inside `prototype2/`; it never touches the parent Nerd workspace or `prototype/`.

## Design System Delta From V1

- **Foundation**: same shadcn/ui new-york style. OKLCH neutral palette as canonical tokens.
- **Icons**: lucide-react.
- **New direction**: *Working Session + Status Bar + Three-Pane*.
- **Token shifts**:
  - Dark backdrop hue moved from warm neutral (107) to cool slate (240) — OLED-friendly.
  - Primary hue moved from lime (130) to emerald (145).
  - Border opacity dropped from 8% to 6% in dark.
  - New tokens: `--color-run`, `--surface-active`, `--surface-muted`, `--status-bar-bg`.
- **Layout primitive**: three-pane shell via `react-resizable-panels`. Title bar (40px) + Command Bar (44px, persistent top) + Status Bar (28px, persistent bottom) all sticky.
- **No telemetry**, no auth, no charts on Overview (decision pending for N6).

## Decisions

- **Platform**: `web` — Vite + React in browser. No Tauri in prototype2.
- **Direction**: total redesign with *Working Session + Status Bar + Three-Pane* mental model.
- **Build path**: code-first, mirroring v1.
- **Voice**: English.
- **Theme default**: dark (OLED-cool slate). User can toggle to light or system.
- **Lockfile isolation**: prototype2 owns its own `package-lock.json`; never touches `prototype/` or the parent workspace.
- **shadcn primitives**: hand-curated (button, badge, separator, kbd) for N0; later milestones add tabs, toggle-group, command, dialog as needed.
- **No analytics charts** in Overview (decision pending for N6; v1 rule carries over).
- **Sticky shell + content-only scroll** in CenterStage; rails stay fixed.
- **Multi-pane persistence**: `react-resizable-panels` `autoSaveId="nerd-v2-layout"` preserves user layout across sessions.
- **Desktop mockup mode**: whole shell is wrapped in a Windows 11-style desktop (wallpaper + centered window frame with OS chrome + bottom taskbar). Signals "desktop app" while the prototype runs in the browser. Visual only; window controls are non-functional in the prototype and will wire to native commands in Tauri production.
- **Sidebar strategy**: a single full-height primary AppSidebar (left of the window) owns brand + nav. Inner project rail was retired — three-pane became two-pane (Center Stage + Inspector Rail). `WorkingSessionToggle` is a global filter (`active`/`all`/`background`) lifted to App root; it is rendered on the **Projects screen** header (next to the search field), not in the sidebar, and is consumed by the Projects list and the command palette's Projects group.
- **Search placement**: the AppSidebar header holds a button that opens the global command palette (`⌘K`). The brand moved to the desktop window chrome (drag region); version `v0.1.0-alpha.1` sits in the sidebar footer beside the theme switcher.
- **Inspector toggle**: the Inspector rail's open/closed state is lifted to App.tsx and exposed via a `PanelRight` button in the StatusBar (replaces the clock on the footer app). The button reads `inspectorOpen` and dispatches `panel.collapse()` / `panel.expand()` via `ImperativePanelHandle`. Drag-to-resize still works when the rail is open; collapsing is the only way to hide it (no auto-hide). The Taskbar's Inspector icon is decorative.

## Blockers

None open for prototype2 scope.

## Review Rule

A milestone is `complete` only after source compiles (`tsc --noEmit`), dev server boots in under 1 second, production build succeeds, light/dark renders correctly, focus ring is visible, and the relevant primitives are recorded in `context/ui-registry.md` (with a `v2` tag where applicable to keep the v1 registry entries intact).
